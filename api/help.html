1. Getting started

Antikythera runs on a Docker host (it does not run on your laptop). You reach it through an SSH tunnel, so nothing is exposed to the network.

Open the tunnel (once per session)

ssh -N \
  -L 18006:127.0.0.1:18006 \
  -L 15173:127.0.0.1:15173 \
  <user>@<docker-host>

Tip: put the two LocalForward lines in your ~/.ssh/config so a plain ssh docker-host opens them. Then open http://localhost:15173.

First run — the setup screen

On a fresh install the UI shows a Setup screen instead of the app. It walks you through everything that is missing:

  • Provider API keys (Google/Gemma, OpenRouter, NVIDIA…) — names only, never shown again
  • Jira credentials (base URL + personal access token)
  • The Slack webhook for notifications
  • The API token (generated for you, shown once — copy it)

Click Finish setup and the app loads. The setup screen only accepts connections from the machine itself (your tunnel counts); afterwards the endpoints are locked.

Where things live

Path (on the Docker host)What
~/.antikythera/Config: .env, .ai_env (secrets, mode 600), ai_config.json, api_token, settings.json
~/antikythera-data/Your data: the board, items, artifacts, Studio graphs, run logs

2. Access & the API token

Every /api/* request needs a bearer token. The UI asks for it once (a small dialog) and keeps it for the session. For scripts and curl:

# The token (on the Docker host):
cat ~/.antikythera/api_token

# Use it:
curl -H "Authorization: Bearer $TOKEN" http://localhost:18006/api/state
  • If ANTIKYTHERA_API_TOKEN is set in the environment, that value is used instead.
  • Missing or wrong token → 401.
  • The token is never written to logs and never returned by any endpoint.
The API docs (Swagger) are off by default. Set ANTIKYTHERA_ENABLE_DOCS=1 and restart to get them at /docs.

3. The board (pipeline)

Ideas move through ten stages. AI agents do the work; you approve at the review gates.

StageWho actsWhat happens
INTAKE → REFINEMENTRefiner (AI)Turns the idea into a spec.md
REVIEW_SPECYouApprove or request revision
ARCHITECTUREArchitect (AI)Writes architecture.md
REVIEW_ARCHYouApprove or request revision
TESTINGTester (AI)Writes a test plan (tests.md)
REVIEW_TESTYouApprove or request revision
APPROVED → EXECUTINGExecutor (AI)Plans tasks and writes files into the item folder
DONE—Finished

Complexity tiers

Each item has a complexity that decides which stages it visits. Set it when creating the item, or leave it on Auto and the refiner picks:

TierVisitsSkips
trivialINTAKE, REFINEMENT, REVIEW_SPEC, EXECUTING, DONEArchitecture + testing stages
simpleadds ARCHITECTURE + REVIEW_ARCHTesting stages
complex defaultall tennothing

Approving and moving

Use the review form on an item (the drawer’s Review tab). Approve records the decision and lets the item move on; Needs revision sends it back to the previous agent stage. Dragging a card works, but the board enforces the rules:

  • You cannot drag an item out of a review stage until it is approved.
  • You cannot drag an item into a stage its tier skips.
  • Both rules can be overridden with the explicit Force move button (the API equivalent is "force": true).
If an agent fails repeatedly (3 times at the same stage), the item is marked blocked with the reason on the card. Fix the cause or force-move the item to retry.

4. Automation Studio

Studio builds an automation by working against live data, one step at a time — not by generating a whole workflow from a prompt. Open the Studio tab.

The four turns

Each turn drafts one node: Query (fetch a list from an adapter) → Fan-out (loop over the results) → AI-transform (run a script over each item) → Conditional-action (test a condition, act on match).

Preview, commit, run

  • Preview runs the draft against your sandbox state — it never writes to the outside world.
  • Commit adds the node to the graph and connects it to the previous one.
  • Run executes the saved graph. dry run is ON by default: a run reports what it would do without writing. Untick the box for a live run.

Node reference

NodeKey fieldsNotes
Queryadapter, action, paramsAdapters: jira, github, internal. Params support {{variable}} placeholders filled from state.
Fan-outsource, iterator_varRuns its child node once per item of the source list.
AI-transformscript or skillA Python script with input, state and loop in scope; runs in a sandboxed subprocess with a time limit.
Conditional-actioncondition, true/false actionsCondition types: equals, contains, regex, in-list, exists — combined with AND/OR. Unmatched items (no false action) go to the undefined queue.

Reading results

Each run gets a log with per-node results and totals. Status is completed, partial (some nodes failed) or failed. The undefined queue holds the latest run’s unmatched items, capped by the graph’s setting. Run logs are kept up to the graph’s max_run_logs (default 50); a per-graph aggregate keeps the running totals.

5. Workflows & templates

Workflows are step-by-step templates run by the engine. The current step shape is {adapter, action, config} — old templates are migrated automatically.

Example: comment on merged PRs

curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -X POST http://localhost:18006/api/workflows/templates -d '{
  "template_id": "pr-release-notes",
  "name": "PR release notes",
  "trigger": {"type": "webhook", "provider": "github"},
  "steps": [
    {"step_id": "S1", "name": "Fetch merged PR",
     "adapter": "github", "action": "fetch_resource",
     "config": {"resource_id": "{{number}}"}},
    {"step_id": "S2", "name": "Comment",
     "adapter": "internal", "action": "add_comment",
     "config": {"item_id": "ID-001", "body": "Released {{number}}"},
     "next_step": "S2"}
  ]}'

Rules the save endpoint enforces

  • Allowed adapters: internal, github, jira, ai. Shell steps are rejected.
  • Every step needs an action; a type key is only allowed for ORCHESTRATOR_TASK (human-in-the-loop) steps.
  • Each adapter’s config is schema-checked (unknown keys rejected).

Running and failing

  • Trigger with POST /api/workflows/trigger {"template_id": "...", "inputs": {...}}.
  • ORCHESTRATOR_TASK steps pause the run until you resume it (the run waits in WAITING_FOR_HUMAN).
  • A failed step retries after 5, 10 and 15 minutes; after that the run is BLOCKED and a recovery card (REC-*) appears on the board. Resume it from the card.
  • On restart, runs left in flight are marked failed with “orphaned: server restart” — resume them manually.

6. Integrations & credentials

The Integrations tab manages connections. Two kinds: native (Jira, GitHub, internal, bob shell — Python adapters) and MCP (external tools launched as processes).

How credentials are resolved

Workflow and Studio steps name an adapter canonically (jira, github, ...). Credentials come from, in order:

  1. An integration with exactly that name.
  2. Any integration using the same adapter (first by name — create one in the UI with the token and URL filled in).
  3. Environment variables (JIRA_PAT, JIRA_BASE_URL, GITHUB_TOKEN...), including what the setup screen wrote.
Secrets are masked as ***** in list responses and never displayed again after saving. A ${env:NAME} value in a config field reads that variable at call time.

7. AI Engine

The AI Engine tab picks the provider and model every agent uses (default: Google Gemma). Keys live in ~/.antikythera/.ai_env and can be set from the tab or the setup screen. Changing the default model takes effect for new runs.

Providers: Google Gemma, OpenAI, NVIDIA NIM, OpenRouter, Anthropic, Ollama, LM Studio and the local bob CLI. If the provider is unreachable the agents fall back to templates and mark items blocked rather than writing junk.

8. Settings

Tunables live under /api/settings (token required) and persist in ~/.antikythera/settings.json. Every value has safe bounds; the API tells you each one’s default and whether a restart is needed.

curl -H "Authorization: Bearer $TOKEN" http://localhost:18006/api/settings

# Change one (retry delays, in minutes):
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -X PATCH http://localhost:18006/api/settings \
  -d '{"retry_delays_min": [2, 5, 10]}'

Tunable today: orchestrator interval, retry delays, poison-item strikes, reap age, bob timeout, executor max tasks, digest interval, Studio queue cap and run-log limit.

9. Backups & operations

Backup

# On the Docker host (nightly cron is documented in docker/README.md):
scripts/backup_data.sh ~/antikythera-data

# Restores: list the archive first, stop the stack, extract, start.
tar -tzf ~/antikythera-backups/automation-ideas-<timestamp>.tar.gz | head

Archives are written mode 600 and rotated (default: keep 14).

Logs

Backend log tail (last 200 lines) is in the AI Engine tab, or GET /api/ai-engine/logs?lines=200. Item timelines are on each card.

Corrupt files

If a state file is ever damaged, the API refuses to serve an empty board: it returns an error naming the file, keeps the original untouched, and saves a copy as <file>.corrupt-<timestamp> beside it. Restore from backup or fix the copy, then restart.

10. Troubleshooting

SymptomCause & fix
401 UnauthorizedMissing/wrong token. UI: re-enter it in the dialog. Scripts: Authorization: Bearer <token> from ~/.antikythera/api_token.
Page won’t load / connection refusedThe tunnel is down, or the stack is not running. Re-run the ssh -N -L ... command; check docker-compose ps on the host.
422 when dragging a cardThe move gate: approve the item first, or use the explicit Force move button. The message says which rule tripped.
Integration github not foundNo integration supplies that adapter. Create one in the Integrations tab (any name, matching adapter, token filled in) or set the environment variable.
Setup screen says “local only”Setup accepts loopback connections only — your SSH tunnel qualifies; a direct remote connection does not.
Item stuck blockedThe agent failed 3 times at the same stage; the reason is on the card. Often the AI provider is unreachable (check the key in the AI Engine tab).
Run BLOCKED with a REC- cardA workflow step exhausted its retries. Fix the cause and resume from the recovery card.
Run FAILED “orphaned: server restart”The stack restarted mid-run. Resume the run; nothing was lost.
Logs tab shows truncatedExpected: the log endpoint caps at 2000 lines / 256 KB and tells the UI when it did.
